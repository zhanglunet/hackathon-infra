## 改了什么

### ③ router/prefix_router.py（全文重写，11,047 → 20,575 字节，仍纯标准库零依赖）

- **路由键**：跳过开头的 system 消息（各会话共用的长 system prompt 不再进入键），
  取剩余对话内容的前 512 字符。同一会话的键是对话的真前缀，随轮次增长不变
  （保缓存命中）；不同会话的对话内容不同，键不同。旧版把 system prompt 也算进键，
  850 字符的共同 system prompt 超过 512，直接让所有请求的键完全相同。
- **rendezvous hashing（HRW）取代哈希取模**：score = sha256(key | backend)，
  取分最高的。增删一个后端时，只有原来落在它的那部分会话迁移。旧版注释写
  「一致性哈希」，实际是 `sha256 % len` 取模，已改。
- **有界负载**：分最高的后端在途数超过 平均值 × (1 + ε)（ε 默认 0.25，
  `--epsilon` 可调）时，顺着分数往下找下一个后端。共同前缀导致热点时自动溢出。
- **后台探活 + 故障转移**：每 5 秒（`--health-interval`）并行探各后端 `/health`
  （单个超时 2 秒），不健康的摘出路由环，恢复后加回；`/health` 端点直接返回
  缓存的探活结果。转发时连接失败（后端刚挂、探活还没发现），在还没给客户端发
  任何字节的前提下立刻重试环上下一个后端；一旦开始向客户端发字节就不再重试
  （旧版 except 里 `_send_bytes(502)` 会往已开始的 SSE 响应里写乱数据，P1-5）。
- **7 个 P1 全改**：`request_queue_size` 1024、`daemon_threads = True`；
  `/health` 与 `/metrics` 改并行抓取（单个超时 3 秒），HELP/TYPE 行取第一个
  健康后端（旧版只取 backend 0）；上游超时默认 21600 秒（与 AIPerf 默认一致，
  `--timeout` 可调）；文档与行为不一致修掉（文件头写默认 4096、代码是 512，
  现统一写 512 并说明 system 消息不计入）；新增 `/router/stats`（各后端在途数、
  累计请求数、健康状态、总路由数与故障转移数）。
- CLI 保持兼容（`--backends/--host/--port/--prefix-chars/--timeout` 原样），
  新增 `--health-interval`、`--epsilon`。`pick_backend(backends, key)` 保留为
  无状态 rendezvous 选法（线上走 `RouterState.rank_backends`）。

### ② Dockerfile

- **P0 `||` 优先级 bug 修掉**：vllm 安装与 flashinfer 回退拆成两个 RUN；
  flashinfer 回退写成 `{ python -c "import flashinfer" || pip install ...; }`
  大括号组（回退本身失败时构建失败）；最后加一行构建期自检
  `RUN python -c "import vllm, flashinfer; print(vllm.__version__)"`。
  flashinfer 锁 `0.7.3`（vLLM 0.34.0 要求，见 #1 的调研）。
- apt 加装 `rdma-core libibverbs1 ibverbs-utils iproute2`（跨机 PD/CP 与 NCCL IB 用）。
- `FROM --platform=linux/amd64` 明确构建平台。
- `docker run` 示例补全：`--device /dev/infiniband --ulimit memlock=-1`、
  权重挂载 `:ro`、缓存目录挂本地 NVMe、NCCL 变量 `-e` 传入示例；
  NCCL_IB_HCA 的 8 个口写明是占位，上机后用 `ibv_devinfo` / `rdma link` 筛
  真正 ACTIVE 的 8 个口再填（见 DAY1-RUNBOOK.md 10:30–11:00 那步）。

### ① serve-qwen27b.sh / serve-deepseek.sh / serve-glm.sh（三处 P2，全改）

- `MODEL_PATH="${MODEL_PATH:-$MODEL_DIR/$MODEL_NAME}"`：允许直接传 MODEL_PATH
  （NFS 目录名不一定和 MODEL_NAME 一致）。
- `LOG_DIR="${LOG_DIR:-./logs}"`：日志目录可配置（容器里代码目录只读时默认
  `./logs` 写不进去会直接退出）。
- 找不到权重时的报错统一改成「请确认 MODEL_DIR / MODEL_PATH 是否指向 NFS 上
  的权重目录（比赛权重已预置，不要自己下载）」，不再提示跑 `download-*.sh`。
  （qwen 那份的报错在 063a64f4 里已改过，本次只统一了措辞；deepseek/glm 两份
  是本次新改。）

### 新增 scripts/distribute-image.sh

- `docker save | zstd` 打包 → 记下包大小 → scp 到 4 台机 → 每台 `docker load` →
  每台 `docker images` 核对在位。节点地址用 `--nodes user@host,...` 或 `R2_NODES`
