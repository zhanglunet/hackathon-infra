# 2026-11-21：Modal 部署代码（Qwen3.8-27B FP8）

## 目标

在 Modal 上跑 Qwen3.8-27B 的 vLLM 服务（OpenAI 兼容接口
`/v1/chat/completions` + `/metrics`），先做短上下文冒烟，再测 272K，
给 2026-11-27 比赛做排练。

## 做了什么

新增 `modal/modal_vllm_qwen27b.py` + `modal/README.md`，已推送到 main。

- 模型：`Qwen/Qwen3.8-27B-FP8`（官方 FP8 版，约 31 GB，7 分片），
  BF16 备选 `Qwen/Qwen3.8-27B`（约 55 GB，18 分片）。
  模型名、启动参数照抄 `serve-qwen27b.sh` / `download-model.sh`。
- vLLM 0.34.0，served-model-name `qwen3.8-27b`，端口 8000。
  启动参数：`--quantization fp8`、`--kv-cache-dtype fp8`、
  `--gpu-memory-utilization 0.90`、`--max-num-seqs 32`、
  `--enable-prefix-caching`、`--enable-per-request-metrics`。
- GPU 开关（环境变量 `MODAL_GPU`）：默认 `A100-80GB`（最便宜）；
  FP8 冒烟切 `H100`；测 272K 切 `H200` 141GB。
- 权重存在 Modal Volume `qwen27b-weights` 里（1 TiB 免费额度），
  下一次就够；下载函数不挂 GPU，只花 CPU 时间。
- 冒烟：`modal run modal/modal_vllm_qwen27b.py --url <部署地址>`，
  4 项（/health、/v1/models、流式 TTFT/TPOT、/metrics），
  逻辑复用 `smoke-test.sh`。

## 已知问题

- **A100 跑不了 FP8 权重**：FP8 需要 Hopper（算力 9.0+）或 Blackwell
  的张量核，A100 是 Ampere（8.0）。代码里加了和 `serve-qwen27b.sh`
  一样的算力检查，A100 + FP8 会直接报错并提示改法（切 H100/H200，
  或 A100 上改 BF16 短上下文冒烟）。不要绕过这个检查。
- **272K 是 YaRN 外推**：模型原生上限 262144，比赛要 272000。
  `MAX_MODEL_LEN=272000` 时自动加 YaRN（factor≈1.04），实验性：
  先跑 EvalScope 精度对照，确认损失 ≤2% 再用。
