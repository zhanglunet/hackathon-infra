# devlog：夜跑队列 nightq（2026-11-26）

## 背景

R2 只有 4 天、没有调试日，DeepSeek 换一次配置要重新加载 511 GB 权重。
`DAY1-RUNBOOK.md` 的「18:00 之后：夜间长任务」要求每晚挂任务，但仓库里没有能自动换配置的工具：
`loadtest/run_ladder.py` 只压一个已经起好的服务，停旧的、起新的、等就绪、出错换下一个都要人做。
用户 2026-11-26 让看看还缺什么，点名问了夜跑队列脚本，于是做了这个。

## 加了什么（新目录 `nightq/`，没动别的代码）

- `nightq/nightq.py`：夜跑队列，纯标准库。按 INI 清单逐个任务「确认端口空着 → 起服务 → 等就绪 →
  按顺序跑步骤 → 停服务并确认端口放开」；任何一步出问题就记原因、停服务、接着跑下一个任务。
  每个任务结束重写 `summary.md`（结果、用时、四档摸高、失败日志最后几行）。
  支持续跑（同一个 `--out` 再跑：成功的跳过，被打断的重跑）、`--retry-failed`、`--only`、
  `--stop-after HH:MM`（到点不再开新任务）、`--dry-run`、同机互斥锁；SSH 掉线不影响。
- `nightq/deepseek-vllm.ini`：DeepSeek 单机 vLLM 配置对照的队列模板（基线、Engram 放显存、DEP8、
  KV 不量化、batched tokens 16K、DSpark 5）。开关全部取自 `serve-deepseek.sh` 文件头。
- `nightq/example-mock.ini`：假服务示例，本机约 15 秒跑完。
- `nightq/selftest.sh`：自测，约 40 秒。
- `nightq/README.md`：用法、队列文件写法、结果怎么看、docker 注意事项。
- `README.md` 文件清单、`DAY1-RUNBOOK.md` §1 和「18:00 之后」各加一处指向。

## 验证（本机 Mac，Python 3.9.6，bash 3.2.57，假服务，$0）

`bash nightq/selftest.sh`：**27 项全过**。

| 场景 | 判定 |
|---|---|
| 服务正常、两步都成功 | 成功；`env` 和 `$NIGHTQ_*` 变量生效 |
| start 命令直接退出 | 服务没起来 |
| 服务一直不就绪 | 服务没起来；残留进程已清掉 |
| 服务进程中途退出 | 服务中途挂了 |
| detached 模式下服务被杀 | 探活连续 3 次不通，判服务中途挂了 |
| 某步超过 `step_timeout` | 步骤超时 |
| 某步返回非 0（stop / continue 两种） | 步骤失败；后面的步骤分别是不跑 / 照常跑 |
| 前面 6 个任务各种失败之后 | 端口都放开了，最后一个任务照常成功 |
| 同一个 `--out` 再跑 | 没有重跑任何任务 |
| `--retry-failed --only` | 只重跑指定的那个，旧目录留成 `.attempt1`，汇总仍列全部任务 |
| 开跑前端口上已有服务 | 判端口被占；原来的服务没被动 |
| 第二个队列用同一把锁启动 | 拒绝启动 |
| 跑步骤时收到 TERM | 退出码 130，任务记为被打断，服务已停，后面的任务没跑；之后能续跑 |
| 队列文件键名写错（`step`） | 开跑前退出码 2，指出是哪个键 |
| 仓库里两个 `.ini` | 都通过 `--dry-run` |
| 真的 `serve-deepseek.sh` + `smoke-test.sh`（`vllm`、`nvidia-smi` 用假的顶替） | 任务成功，冒烟 4/4；服务日志落在任务目录；`tee` 管道起的服务停干净了 |

## 顺带发现

macOS 自带的 bash 3.2 在 UTF-8 环境下，会把「`$变量）`」里全角括号的第一个字节并进变量名。
`serve-*.sh`、`smoke-test.sh` 等脚本里这种写法有 30 多处，又开着 `set -u`，
所以在 Mac 上直接跑会报 `unbound variable`（本机实测 `serve-deepseek.sh:139`；设 `LC_ALL=C` 后正常）。
比赛机和镜像是 Ubuntu 24.04，bash 版本不同，**是否受影响未核实**；脚本没改，自测里那一节设了 `LC_ALL=C`。
