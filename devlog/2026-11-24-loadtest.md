# 2026-11-24 四档场景 SLO 压测脚本（loadtest/）

## 结论

- 新建 `loadtest/`：按规则「二.3 性能标准」的四档场景 × 并发阶梯压测推理服务，判定 P90 SLO，输出每档摸高并发和 Goodput（`report.md`）。
- 默认用 NVIDIA AIPerf 发请求（和评审组一致），另有只用标准库的内置客户端做备胎和交叉核对。
- 只在本地假服务上验证过整条链路，**没有对真实模型跑过，没有任何真机数字**。未上 GPU，$0。
- 机器：作者的 Mac（Apple Silicon）；AIPerf 0.14.0（Python 3.12 虚拟环境）；数据和压测脚本本身用系统 Python 3.9 也能跑。

## 做了什么

| 文件 | 作用 |
|---|---|
| `scenarios.py` | 四档场景定义，照抄规则表（注意高压档阶梯只到 64） |
| `make_datasets.py` | 造数据：混合长度（对数正态，截断 256K）、共享前缀模拟缓存命中、自然文本（Python 标准库源码），每档每级一个 JSONL + 预热文件 |
| `run_ladder.py` | 主入口：预热 → 抓 `/metrics` → 压测 → 抓 `/metrics` → 判定 → 报告；默认某级不过线就停 |
| `aiperf_engine.py` | 调 AIPerf，换算成统一字段 |
| `builtin_client.py` | 内置客户端（流式，计 reasoning token） |
| `report.py` | 报告；多个结果目录并排对比摸高 |
| `mock_server.py` | 假服务：串行 prefill、前缀缓存（LRU）、decode 随并发变慢、`/metrics` |
| `selftest.sh` | 一键自检 |

## 验证（全部在本地假服务上，数字本身没有意义）

1. **数据生成**：全量（scale 1.0）约 1 秒、508 MB。输入均值：agent 49,866–50,055，coding 99,636–99,956，longgen 994–995，stress 32,037；理论命中 agent 0.70、coding 0.90。
2. **缓存命中构造有效**：实测命中（`/metrics` 增量）coding 0.87（理论 0.88，缩小版数据）。多地址（两个假服务）按会话粘滞路由，命中仍为 0.87，负载约各一半。
3. **判定逻辑**：把假服务调慢后，stress 在并发 32 因 P90 TTFT 31.99s > 20s 判不过线、longgen 在并发 16 因 P90 TPOT 75.6ms > 75ms 判不过线，都按预期停止往上测，报告摸高分别是 16 和 8。
4. **两个引擎互相核对**：同一假服务、同一份数据，coding/stress 并发 8、16 的 P90 TTFT、P90 TPOT、Goodput 相差约 2% 以内（例：stress c16 P90 TTFT 2.88s vs 2.89s）。
5. **错误处理**：假服务上下文上限设 500 → 全部 400，两引擎都判 100% 错误、不过线；上限设 3000 → 24 个请求里 4 个失败，两引擎都记 4/24。
6. **tokenizer 模式**：用本地训练的小 tokenizer 验证代码路径：数据里记录的长度与重新编码一致（2566 vs 2566）。
7. **自检脚本**：`selftest.sh` 内置引擎约 2.5 秒、AIPerf 引擎约 29 秒，四档都有结果。

## 发现并已处理的问题

- **重跑同一份数据会虚高**：第二次跑时服务缓存里还有上一次的内容，stress 档（目标命中 0）实测命中 0.94。改为每次运行给所有请求开头加随机标记；修复后同一服务上连续两次运行，stress 实测命中回到 0.00。
- **结果目录混用**：复用 `--out` 时旧结果会混进报告。现在已有结果就拒绝，需 `--force`。
- **AIPerf `session_id` 陷阱**：single_turn 数据带 `session_id` 时 AIPerf 会拼成多轮对话、带上前面的回复。转给 AIPerf 的数据不带它。

## 关于 AIPerf 的发现（读 0.14.0 的 `--help` 和源码；真机未验证）

- 内置 SPEED-Bench 数据类型（`speed-bench-throughput-1-k` 等），规则里长文本档就是 SPEED-Bench，评审组可能直接这样跑。未核实。
- 内置智能体轨迹回放（`weka-trace`、`tracelab`、`--scenario agentx`）。未核实官方「多轮编程轨迹」是否这类格式。
- vLLM 加 `--enable-prompt-tokens-details` 后 AIPerf 能按请求统计缓存命中 token；建议启动脚本加上（zhanglunet 的文件，未改）。
- 多个 `--url` 时 AIPerf 只支持轮询，不按会话粘滞。多副本对外只给一个地址时，前面的负载均衡要按会话/前缀粘滞，否则命中率会掉。
